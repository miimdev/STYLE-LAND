# استایلند | STYLELAND

فروشگاه فارسی و راست‌به‌چپ پوشاک و اکسسوری، ساخته‌شده با HTML، CSS و JavaScript خالص و بدون مرحلهٔ build. رابط برای موبایل طراحی شده و اطلاعات عمومی فروشگاه را از Supabase می‌خواند؛ در قطع اتصال، کاتالوگ نمونه و سبد و علاقه‌مندی‌های محلی همچنان در دسترس‌اند.

- **دمو:** [مشاهده استایلند](https://miimdev.github.io/STYLE-LAND/)
- **مخزن:** [miimdev/STYLE-LAND](https://github.com/miimdev/STYLE-LAND)
- **Supabase:** [داشبورد پروژه stayland](https://supabase.com/dashboard/project/tpueescgcimeesxrmpgj)

## امکانات

- صفحهٔ اصلی با اسلایدر، دسته‌بندی، پیشنهادها، برندها و مجله؛ جستجوی زنده و منو و سبد کشویی.
- فیلتر و مرتب‌سازی محصولات با ثبت وضعیت در URL، نمایش سریع، انتخاب رنگ و سایز، علاقه‌مندی و سبد پایدار.
- تسویه‌حساب سه‌مرحله‌ای با اعتبارسنجی فارسی، کد `STYLE10`، انتخاب ارسال و کد پیگیری؛ حساب با ایمیل/رمز عبور، سفارش‌ها، آدرس‌ها و نظرها.
- داده‌های نمونه شامل ۲۴ محصول در ۶ دسته، ۶ برند، ۶ مقاله، ۷۲ نظر و ۱۳ جدول با RLS. سبد و علاقه‌مندی مهمان پس از ورود با حساب ادغام می‌شوند.
- نمایش آفلاین با داده و تصاویر محلی، پشتیبانی از صفحه‌کلید، قفل تمرکز در پنجره‌ها، RTL، اعداد فارسی، تصاویر تنبل، SEO و حالت کاهش حرکت.

## توجه مهم دربارهٔ نسخهٔ نمایشی

این نمونه **فروشگاه عملیاتی یا درگاه پرداخت واقعی نیست**. تمام محصولات، قیمت‌ها، نظرها، اطلاعات تماس، مزایا و اطلاعات حمل نمونه هستند. سفارش‌های ثبت‌شده با وضعیت `test` و `not_paid` ذخیره می‌شوند؛ گزینه‌های پرداخت و ارسال صرفاً شبیه‌سازی‌اند و هیچ پول یا کالایی جابه‌جا نمی‌شود. در حالت آفلاین کد محلی صرفاً نمایشی است و سفارشی به سرور فرستاده نمی‌شود. کد موبایل نیز فقط نمایش رابط است و هیچ پیامکی ارسال نمی‌کند و کسی را وارد حساب نمی‌کند.

برای استفادهٔ تجاری واقعی، اطلاعات و موجودی واقعی، شرایط حقوقی و تماس معتبر، سرویس ارسال و درگاه پرداخت سمت سرور، وب‌هوک‌های تأیید تراکنش، محدودسازی و پایش سوءاستفاده و ارسال ایمیل اختصاصی باید متصل و بررسی شوند. تأیید ایمیل Supabase فعال است؛ سرویس ایمیل پیش‌فرض Supabase برای ارسال عمومی محدود است و برای ثبت‌نام مشتریان واقعی به SMTP اختصاصی و دامنهٔ تأییدشده نیاز دارد.

## فناوری و ساختار

```text
├── *.html                 صفحات مستقل و قابل انتشار روی GitHub Pages
├── css/                   متغیرها، پایه، اجزا و استایل صفحات
├── js/                    کلاینت Supabase، دادهٔ محلی، وضعیت، رابط، فیلتر و تسویه
├── assets/                تصویر هیرو، نسخهٔ محلی تصاویر نمونه و فونت جایگزین
├── supabase/migrations/   ساخت جداول، RLS و توابع تراکنشی
├── supabase/seed.sql      داده‌های نمونه؛ قابل اجرای مجدد
└── tests/                 آزمون‌های مستقل داده و ساختار
```

کتابخانهٔ `supabase-js` از CDN بارگذاری می‌شود. فونت Vazirmatn از Google Fonts درخواست می‌شود و نسخهٔ محلی دارای مجوز OFL برای قطعی شبکه در نظر گرفته شده است. تصاویر محصول از Unsplash با پارامتر عرض و کیفیت هستند و نسخه‌های کوچک محلی، جایگزین در قطع شبکه‌اند؛ تصویر هیرو تولیدشده با هوش مصنوعی است. نام برندها و تصاویر فقط دادهٔ نمایشی‌اند و نشانهٔ همکاری تجاری نیستند.

## اجرا و پیکربندی توسعه

هیچ ابزار build لازم نیست. سایت باید از یک سرور HTTP ساده سرو شود (ES Modules با `file://` اجرا نمی‌شوند):

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. نشانی پروژه و کلید **عمومی anon** در `js/config.js` هستند؛ نمونهٔ پیکربندی بدون کلید در `.env.example` آمده است. کلید `service_role` هرگز در مرورگر یا مخزن قرار نمی‌گیرد. اگر پروژهٔ Supabase دیگری استفاده می‌شود، migrationها و seed به‌ترتیب اجرا و نشانی و کلید عمومی جایگزین شوند. همهٔ مسیرهای فایل و لینک‌های داخلی نسبی‌اند و `.nojekyll` برای GitHub Pages موجود است.

`place_order` با `SECURITY DEFINER` و مسیر جستجوی محدود، هویت، موجودی هر ترکیب، قیمت سرور، کوپن، روش ارسال و اطلاعات گیرنده را در یک تراکنش بررسی می‌کند. کاربر تنها سفارش‌های خودش را می‌خواند؛ ثبت مستقیم سفارش توسط مرورگر مجاز نیست. همهٔ مبالغ رابط به تومان هستند.

## آزمون

```bash
node --test tests/data.test.mjs
```

جریان‌های مرورگر و اندازه‌های ۳۲۰ تا ۱۹۲۰ پیکسل نیز با مرورگر headless بررسی شده‌اند. تأیید واقعی تحویل ایمیل و درگاه پرداخت به زیرساخت‌های اختصاصی بالا وابسته است.
