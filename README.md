# استایلند | STYLELAND

فروشگاه فارسی و راست‌به‌چپ پوشاک و اکسسوری، ساخته‌شده با HTML، CSS و JavaScript خالص و بدون مرحلهٔ build. رابط برای موبایل طراحی شده و اطلاعات عمومی فروشگاه را از Supabase می‌خواند؛ در قطع اتصال، کاتالوگ نمونه و سبد و علاقه‌مندی‌های محلی همچنان در دسترس‌اند.

- **دمو:** [فروشگاه منتشرشده روی GitHub Pages](https://miimdev.github.io/STYLE-LAND/)
- **مخزن:** [miimdev/STYLE-LAND](https://github.com/miimdev/STYLE-LAND)
- **Supabase:** [داشبورد پروژه stayland](https://supabase.com/dashboard/project/tpueescgcimeesxrmpgj)

## امکانات

- صفحهٔ اصلی با اسلایدر، دسته‌بندی، پیشنهادها، برندها و مجله؛ جستجوی زنده و منو و سبد کشویی.
- فیلتر و مرتب‌سازی محصولات با ثبت وضعیت در URL، نمایش سریع، انتخاب رنگ و سایز، علاقه‌مندی و سبد پایدار.
- تسویه‌حساب سه‌مرحله‌ای با اعتبارسنجی فارسی، کد `STYLE10`، انتخاب ارسال و کد پیگیری؛ حساب با ایمیل/رمز عبور، سفارش‌ها، آدرس‌ها و نظرها.
- داده‌های نمونه شامل ۲۴ محصول در ۶ دسته، ۶ برند، ۶ مقاله، ۷۲ نظر و ۱۳ جدول با RLS. سبد و علاقه‌مندی مهمان پس از ورود با حساب ادغام می‌شوند.
- رندر فوری کاتالوگ محلی و دریافت اطلاعات سرور در پس‌زمینه، تصاویر بهینهٔ WebP، لوگوی برداری اختصاصی و سه تصویر کمپین ساخته‌شده با هوش مصنوعی.
- اسلایدر با کنترل توقف، حرکت نرم و رعایت تنظیم کاهش حرکت، پشتیبانی از صفحه‌کلید، قفل تمرکز در پنجره‌ها، RTL، اعداد فارسی، تصاویر تنبل و SEO.
- دو جایگاه مجوز در فوتر فقط **نمونهٔ نمایشی و بدون اعتبار** هستند؛ دکمه‌هایشان توضیح صریح می‌دهند و به صفحهٔ تأیید جعلی هدایت نمی‌کنند.

## توجه مهم دربارهٔ نسخهٔ نمایشی

این نمونه **فروشگاه عملیاتی یا درگاه پرداخت واقعی نیست**. تمام محصولات، قیمت‌ها، نظرها، اطلاعات تماس، مزایا و اطلاعات حمل نمونه هستند. دو جایگاه مجوز فوتر نیز گواهی یا اینماد واقعی نیستند. سفارش‌های ثبت‌شده با وضعیت `test` و `not_paid` ذخیره می‌شوند؛ گزینه‌های پرداخت و ارسال صرفاً شبیه‌سازی‌اند و هیچ پول یا کالایی جابه‌جا نمی‌شود. در حالت آفلاین کد محلی صرفاً نمایشی است و سفارشی به سرور فرستاده نمی‌شود. کد موبایل نیز فقط نمایش رابط است و هیچ پیامکی ارسال نمی‌کند و کسی را وارد حساب نمی‌کند.

برای استفادهٔ تجاری واقعی، اطلاعات و موجودی واقعی، شرایط حقوقی و تماس معتبر، سرویس ارسال و درگاه پرداخت سمت سرور، وب‌هوک‌های تأیید تراکنش، محدودسازی و پایش سوءاستفاده و ارسال ایمیل اختصاصی باید متصل و بررسی شوند. تأیید ایمیل Supabase فعال است؛ سرویس ایمیل پیش‌فرض Supabase برای ارسال عمومی محدود است و برای ثبت‌نام مشتریان واقعی به SMTP اختصاصی و دامنهٔ تأییدشده نیاز دارد.

## فناوری و ساختار

```text
├── *.html                 صفحات مستقل و قابل انتشار روی GitHub Pages
├── css/                   متغیرها، پایه، اجزا و استایل صفحات
├── js/                    کلاینت Supabase، دادهٔ محلی، وضعیت، رابط، فیلتر و تسویه
├── assets/                لوگوی SVG، تصاویر بهینه، فونت جایگزین و SDK محلی
├── fonts/style.ttf        فونت متغیر محلی سایت و مجوز OFL کنار آن
├── supabase/migrations/   ساخت جداول، RLS و توابع تراکنشی
├── supabase/seed.sql      داده‌های نمونه؛ قابل اجرای مجدد
└── tests/                 آزمون‌های مستقل داده و ساختار
```

کتابخانهٔ `supabase-js` نسخهٔ ثابت ۲٫۱۱۸٫۰ ابتدا از CDN بارگذاری می‌شود و در صورت تأخیر یا مسدودبودن CDN، نسخهٔ محلی همان کتابخانه در `assets/vendor/` به کار می‌رود. فونت اصلی مستقیماً از `fonts/style.ttf` خوانده می‌شود؛ چون فایل اختصاصی ارائه نشده بود، این فایل فعلاً نسخهٔ متغیر Vazirmatn با مجوز OFL است. نسخه‌های WOFF2 محلی نیز جایگزین‌اند و فونت خارجی بارگذاری را متوقف نمی‌کند.

تصاویر نمونهٔ Unsplash ابتدا به‌شکل WebP محلی سرو می‌شوند و JPEG محلی و نشانی Unsplash به‌ترتیب جایگزین‌اند. تصویر هیرو و تصاویر جدید بخش کالکشن‌ها با هوش مصنوعی ساخته شده‌اند. نام برندها و تصاویر فقط دادهٔ نمایشی‌اند و نشانهٔ همکاری تجاری نیستند.

## اجرا و پیکربندی توسعه

هیچ ابزار build لازم نیست. سایت باید از یک سرور HTTP ساده سرو شود (ES Modules با `file://` اجرا نمی‌شوند):

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. نشانی پروژه و کلید **عمومی anon** در `js/config.js` هستند؛ نمونهٔ پیکربندی بدون کلید در `.env.example` آمده است. کلید `service_role` هرگز در مرورگر یا مخزن قرار نمی‌گیرد. اگر پروژهٔ Supabase دیگری استفاده می‌شود، migrationها و seed به‌ترتیب اجرا و نشانی و کلید عمومی جایگزین شوند. همهٔ مسیرهای فایل و لینک‌های داخلی نسبی‌اند و `.nojekyll` برای GitHub Pages موجود است.

`place_order` با `SECURITY DEFINER` و مسیر جستجوی محدود، هویت، موجودی هر ترکیب، قیمت سرور، کوپن، روش ارسال و اطلاعات گیرنده را در یک تراکنش بررسی می‌کند. کاربر تنها سفارش‌های خودش را می‌خواند؛ ثبت مستقیم سفارش توسط مرورگر مجاز نیست. همهٔ مبالغ رابط به تومان هستند.

## آزمون

```bash
node --test tests/data.test.mjs
```

آزمون‌های مرورگر به Playwright و یک مرورگر Chromium نیاز دارند؛ `tests/fast-start.cjs` همچنین از `@supabase/supabase-js@2.118.0` برای پاسخ‌های آزمایشی استفاده می‌کند. وابستگی‌های آزمون وارد سایت نمی‌شوند:

```bash
CHROME_BIN=/path/to/chromium node tests/browser-smoke.cjs
CHROME_BIN=/path/to/chromium node tests/navigation-browser.cjs
CHROME_BIN=/path/to/chromium node tests/fast-start.cjs
```

این آزمون‌ها عرض‌های ۳۲۰ تا ۱۹۲۰، کنترل‌ها و جریان خرید، وضعیت اتصال کند، حفظ ورودی‌ها، ادغام سبد، فونت و تصاویر جایگزین را بررسی می‌کنند. APIهای ورود، سفارش آزمایشی و جداسازی کاربران نیز روی پروژهٔ متصل بررسی شده‌اند. تأیید واقعی تحویل ایمیل و پرداخت به زیرساخت‌های اختصاصی بالا وابسته است.
